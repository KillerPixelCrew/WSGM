# Issue 239 storage runtime fixes

Scope: `GameLibraryService.Storage.cs` and `ManagedShortcutMonitor.cs`, preserving the partial fixes
already present when dispatched. The coordinator owns shared/Core changes, `GameLibraryService.cs`,
formatting and validation beyond the bounded source check.

| Finding | Disposition                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M2      | Identical serialized portable recipes skip manifest publication and revision increments, including readable write-protected cards. Missing or changed recipes still require publication. The coordinator owns per-title failure handling in Apply.                                                                                                                                                                                                                                    |
| M3      | Removal dispatch uses `CancellationToken.None` after `MarkDeletionDispatched`; earlier reads and admission remain cancellable. `DeletionDispatched` still prevents automatic retry after an uncertain native write.                                                                                                                                                                                                                                                                   |
| M4      | Refresh drops orphaned or invalid staged actions, and cancellation can remove an action whose row disappeared. Apply snapshots actions and copied checkpoints together under `_gate`, reports ordinary storage failures per action, clears failed actions for explicit review, and continues other actions/titles. State-index failures and cancellation still propagate.                                                                                                             |
| M5      | Binding acceptance rebinds every cached library inventory record, including recipes absent from the manifest and pending-deletion records. It preserves `InventoryRemoved`, normalizes legacy relative paths before strict resolution, and lets later reconciliation prune confirmed missing content. A malformed cached portable recipe reports its own error and cannot authorize deletion of that title; other entries remain reconcilable.                                        |
| M6      | Known libraries migrate only while `MigrationPending` is set; no matching migrated rows means no migration index writes. An existing foreign manifest is not adopted through migration. Missing legacy recipes can be published through the normal import/reconciliation flow rather than refreshing the accepted checkpoint repeatedly.                                                                                                                                              |
| L1      | An unknown unsupported manifest reports zero locally cached titles instead of counting non-managed records with null content.                                                                                                                                                                                                                                                                                                                                                         |
| L5      | Importing from a foreign existing manifest requires explicit binding review and Apply. Import from a new blank card still creates the initial manifest through the authorized import flow. Migration also refuses to adopt a foreign existing manifest implicitly.                                                                                                                                                                                                                    |
| L6      | Title Recheck restricts manifest path inspection/pruning, cached recipe reconciliation, shortcut cleanup and published row changes to that title. Library Recheck restricts cleanup to that library. A title check does not advance the full-library validation timestamp. Manifest revision publication remains atomic for the whole document, and the existing collection projection sync remains shared.                                                                           |
| L8      | Cleanup retains every `AppId == 0` receipt and reports unconfirmed creation. It does not infer absence from a detail read for id zero, forget the receipt, retry creation or remove an unproven shortcut. Exact command resolution is deliberately deferred rather than adding a persistence API in this worker's scope.                                                                                                                                                              |
| L9      | The monitor checks emulator initialization after both wake and timeout before consuming the pending full-check flag. Recovery cannot publish premature emulator-unavailable state from the timeout path.                                                                                                                                                                                                                                                                              |
| L10     | The second settled storage observation logs its failed result using the existing availability error key.                                                                                                                                                                                                                                                                                                                                                                              |
| L20     | State-index failures remain visible and fatal. Storage-read catch filters exclude `ImportStateException`, including migration and reconciliation; a failed `SaveLibrary` in a manifest error handler propagates rather than being hidden or treated as success. The review's suggestion to suppress that failure is rejected because the launch safety checkpoint was not persisted.                                                                                                  |
| L21     | Preserve the conservative launch block while a known manifest is unreadable, missing, malformed or unsupported. A failed read never clears `RepairRequired`; unsupported schemas still offer no Repair action. A successful bounded reconciliation clears the guard, and the existing second settled observation recovers transient mount failures. Leaving launches enabled during an unreadable manifest would trust stale cached recipes, so that proposed relaxation is rejected. |

API changes:

- Private `ApplyStorageActionsAsync(CancellationToken)` now returns `Task<List<string>>`. The
  coordinator confirmed that `ApplyCoreAsync` consumes the problems, including storage-only Apply.
- Private `CleanRemovedContentAsync` now takes
  `(CancellationToken token, List<string> problems, string requestedLibrary, string requestedContent)`
  to constrain destructive cleanup to the request. Empty scope strings retain full-recheck behavior.
- No public API or Core persistence signature changed.
