# Source map

Use this page to find the implementation behind a feature and the documentation that explains its
contracts. The inventory follows the tracked source and [`WSGM.slnx`](../WSGM.slnx), not leftover
`bin`, `obj`, publish or staging directories. [Architecture](architecture.md) follows the
cross-system runtime flow; this page maps that flow back to projects and folders.

This is a map of all first-party source areas, not a claim that every private method has a separate
API article or that every Windows path has been tested on hardware. Public C# XML documentation is
emitted by [`Directory.Build.props`](../Directory.Build.props); signatures and their local comments
remain the API reference alongside the behavior documents. Device SDK contracts have a dedicated
[reference](../src/WSGM.Device.Sdk/docs/reference.md). Dated observations in the documents retain
their original scope and are not current test results.

## Linked sources and native payloads

[`src/Shared`](../src/Shared) has no standalone project. Its source is linked explicitly by the
consuming `.csproj` files, so a change can affect several executables:

| Folder     | Shared contract                                                                                                                                     |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Boot/`    | Atomic files and the minimal service boot manifest.                                                                                                 |
| `Process/` | Command-line encoding, scheduled tasks, Explorer-parent process startup, session names, child Steam controller-exclusion cleanup and rotating logs. |
| `Install/` | Canonical install/staging layout shared by setup and runtime.                                                                                       |
| `Launch/`  | Packaged-launcher command serialization and parsing.                                                                                                |
| `Interop/` | Common Kernel32 and HidHide control declarations/helpers.                                                                                           |
| `Gpu/`     | Driver runtime, state file, descriptors and write admission shared by vendor packages.                                                              |

The C++ sources maintained here are `Avalonia.LiveBackdrop/Native/Backdrop.cpp` and
`WSGM.PackagedLaunch/Bridge/`. IR firmware sources and its build-time remote embedding tool live in
`WSGM.Plugin.Ir/Firmware/`. `src/WSGM/Native/` and the packaged launcher's `Native/UwpBridge/` are
staging destinations for built payloads, not an additional managed project or a place to edit the
original native implementation.

## Following one request end to end

1. Find the entry point: `Program`/`App` for process modes, `ShellSession` for a resident service,
   an Overlay/Settings handler for a local action, or `SteamUiSessionHost` and a typed backend for a
   Steam page command.
2. Follow the owner of the state. Core stores and pure policy decide persisted intent; Shell
   coordinates live work. Views read projections and submit intent.
3. Follow the reusable boundary: device/common SDK, SteamUiToolkit, WindowsDeviceControl, Steam
   Input pipe, VIIPER or the relevant native interop seam. Do not infer implementation from the UI
   label alone.
4. Follow the result back: observed state, command outcomes and generation checks become a
   dispatcher update or a Steam state publication. Uncertain writes remain distinguishable from
   rejected or never-sent work.
5. Read the paired leave/stop/dispose path and the focused test cases. Surface close, generation
   replacement, disconnect, suspend and whole-session shutdown need not have identical lifetimes.
